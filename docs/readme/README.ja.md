Mangayomi は、NAS にすでに保存しているコミックのアーカイブや画像フォルダーのインデックスを作成し、フォルダー構成から作者とシリーズを判別して、レスポンシブな Web リーダーで配信します。このリーダーは、スマートフォンやタブレットに PWA としてインストールできます。Go 製のサーバーと React 製のフロントエンドで構成され、SQLite をバックエンドとする 1 つの Docker イメージとしてパッケージ化されています。

> [!IMPORTANT]
> Mangayomi は現在も活発に開発中です。アップグレードの前には `config/` をバックアップしてください。また、インスタンスをネットワークに公開する前に、[デプロイ時のセキュリティ](../operations/security.md)に関する注意事項を確認してください。削除機能は、ストレージからファイルを完全に削除します。

## 主な機能

- **あなたのフォルダーを、あなたの構成のままで。** `/data` 以下の任意のフォルダーをライブラリとして追加し、サブフォルダーを除外して、`{author}/{series}` のようなパターンでフォルダー構成を指定できます。保存する前に、各作品がどのように解析されるかをプレビューで確認できます。
- **アーカイブと画像フォルダーに対応。** `.zip` または `.cbz` ファイルは 1 つの作品です。画像を直接含むフォルダーも 1 つの作品として扱われ、そのフォルダー名は作者やシリーズではなくタイトルになります。
- **差分スキャンと定期スキャン。** 必要なときに、または 1〜24 時間ごとにスキャンできます。変更のないファイルはスキップされ、ライブラリのルートにアクセスできない場合でもインデックスが消去されることはありません。
- **スマートフォンのために作られたリーダー。** 右から左・左から右の読む方向（シリーズごとに記憶）、単ページ・見開き・自動のページレイアウト、横長の見開きページの単独表示、タップ領域、スワイプ、キーボードショートカット、進捗の自動同期に対応しています。
- **慎重な削除。** 1 つの作品、複数選択した作品、シリーズ全体、または作者のすべての作品を削除できます。最初のステップで削除されるすべてのファイルとフォルダーが一覧表示され、次のステップで明示的な承認を求められます。
- **軽量でプライベート。** 単一ユーザーのパスワードによるサインイン。外部サービスもテレメトリも使用しません。

## クイックスタート

### 1. デプロイ用ディレクトリを準備する

[`docker-compose.yml`](../../docker-compose.yml) とこのリポジトリの残りのファイルを Docker ホストに配置します（イメージはローカルでビルドされます）。ポート、イメージ、ファイルを所有するユーザーを変更する場合は、必要に応じて [`.env.example`](../../.env.example) を `.env` にコピーしてください。

### 2. `/data` を漫画の保存先に向ける

`docker-compose.yml` の `./data:/data` ボリュームを編集し、漫画の共有フォルダーを指すようにします（例：`/path/to/manga:/data`）。`.env` の `PUID` と `PGID` には、それらのファイルの所有者を設定します（NAS 上で `id` を実行すると確認できます）。

### 3. Mangayomi を起動する

```sh
docker compose up -d --build
```

<http://127.0.0.1:8080> を開いてパスワードを作成し、**Settings → Libraries**（設定 → ライブラリ）からライブラリを追加します。詳しい手順は[はじめに](../user/ja/getting-started.md)を参照してください。

## ランタイムデータ

| ホスト側のパス | コンテナ側のパス | 用途 | バックアップ |
| --- | --- | --- | --- |
| `./config` | `/config` | SQLite データベース（ライブラリ、進捗、セッション）と表紙のキャッシュ | 必要 |
| `./data` | `/data` | 漫画ファイル。閲覧時は読み取りのみで、書き込みは削除時だけ | ご自身のバックアップで管理 |

これらのランタイムディレクトリはコミットしないでください。個人的なメディア、パスワードのハッシュ、セッション情報が含まれている可能性があります。

## セキュリティとプライバシー

サインインとヘルスチェックを除くすべての API 呼び出しには、単一ユーザーのパスワードが必要です。
Mangayomi は外部へのネットワークリクエストを一切行いません。脆弱性の疑いがある場合は、[SECURITY.md](../../SECURITY.md) に記載の非公開の手順で報告してください。また、ログや診断情報を共有する前に [PRIVACY.md](../../PRIVACY.md) を確認してください。
